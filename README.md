# All Translator

Minecraft (NeoForge / Fabric, MC 26.2) 用の翻訳Mod。
アイテム名・ツールチップ・エンティティ名・チャットなど、ゲーム内のテキストを
ユーザーが設定した外部翻訳APIを使って翻訳します。

Mod自体は翻訳APIを提供しません。利用するAPI(ChatGPT等のOpenAI互換、LM Studio等の
ローカルLLM、Anthropic、Gemini、DeepL、Google Cloud Translation v2、無償の
Google Translate Web版など)はご自身で設定画面から登録してください。

## 主な機能

- **既存翻訳の優先使用**: 対象言語のMinecraft/mod言語ファイル、または
  `config/alltranslator/lang/<言語コード>.json` に有効な翻訳が既にある場合、
  APIを一切呼ばずそのまま使用します。
- **翻訳対象**: アイテム名、ツールチップ、エンティティ名(プレイヤー名は対象外)、
  プレイヤーチャット、`/tellraw`、`/msg`・`/tell`・`/w`・`/teammsg`、`/title`、
  実績・レシピのトースト通知、実績のチャット告知、ボスバー名、
  他modの設定画面(vanilla部品、libIPN、UI Lib)。
- **翻訳対象の項目別ON/OFF**: 設定画面の「翻訳対象」から、項目ごとに切り替えられます。既定は全てオフで、意図しないAPIの大量消費を防ぎます(オンにした項目だけが翻訳されます)。
- **複数API設定 + 自動フェイルオーバー**: 優先度付きで複数のAPIを登録でき、
  レート制限・クォータ超過・認証失敗などに応じて自動的に次のAPIへ切り替えます。
  一定時間後に自動で復帰を試みます。
  空の応答や、プレースホルダー(`%s` など)が欠落した訳文も失敗として扱い、次のAPIに回します。
- **API選択方式**: 設定画面(サーバー設定画面も同じ)で「優先度順」(既定)と「分散」を切り替えられます。
  「分散」は、実行中のリクエストが少ないAPIから順に使い、複数のAPIに処理を振り分けます。
  サーバーでは、OPが設定画面から変更でき、再起動なしで反映されます。
- **対応プロバイダ**: OpenAI互換(ChatGPT用)、LM Studio、Ollama、
  Anthropic(Claude)、Gemini、DeepL、Google Cloud Translation v2、
  Google Translate Web版(無償・非公式、チャット専用)、汎用REST、サーバー経由(プロキシ)。
- **サーバー対応**: サーバー側per-player翻訳、プレイヤーごとの言語設定、
  サーバー翻訳窓口(クライアントがAPIキーを持たずにサーバーのAPIで翻訳)、
  OPがゲーム内でサーバー設定を編集できる設定画面。
- **Mod jar一括翻訳**: 他modのjarに同梱された英語の言語ファイルのうち、
  対象言語のものが無いmodを検出し、確認のうえ一括翻訳して、常時有効なリソースパックとして適用します。
- **永続キャッシュ**: 翻訳結果(チャットを除く)をワールドセーブ内に保存し、
  API呼び出しを最小限に抑えます。
- **API状態のスコアボード表示**: 有効なAPIごとの実行中リクエスト数・状態・待機件数を
  サイドバーに表示できます(既定はオフ)。
- **同時リクエスト数の調整**: 設定画面から変更できます(ローカルLLM向け)。
- **JEI連携**(Fabricで実機確認済み): JEIの検索で、アイテムを翻訳後の名前でも元の(英語の)名前でも検索できます。
  `翻訳を有効にする`と`アイテム名`の翻訳がオンのときだけ働きます。詳しくは「既知の制限」の「JEI連携」を参照してください。

## インストール

1. NeoForge または Fabric(対応バージョンのMod Loader)を導入
2. `alltranslator-fabric-<version>.jar` または `alltranslator-neoforge-<version>.jar`
   を `mods` フォルダに配置
3. ゲームを起動後、`M`キー(キー設定から変更可能)で設定画面を開き、
   翻訳APIを1つ以上登録してください

設定画面は次のどれからでも開けます(同じ画面、同じ設定です)。
`M`キー、Mod Menu(Fabric)、NeoForgeの「Mods」画面の設定ボタン。

## 基本的な使い方

1. `M`キーで設定画面を開き、「API」から翻訳APIを追加する(プロバイダ、エンドポイント、APIキー)
2. 「翻訳対象」で、翻訳したい項目をオンにする(既定は全てオフです。オンにした項目だけ、翻訳APIが呼ばれます。v1.0.0から更新した場合も全てオフになります)
3. 対象言語は、既定ではMinecraftの表示言語です。設定画面の対象言語欄で変更できます
   (空欄は表示言語に従います)
4. ローカルLLMを使う場合は、下の「ローカルLLMを使う場合の注意」を確認してください

## キーとコマンド

| 操作 | 内容 |
|---|---|
| `M`キー | 設定画面を開く |
| `K`キー | `/alltranslator refresh` を実行する |

コマンドは `/alltranslator`(短縮形 `/at`) です。

| コマンド | 内容 | 権限 |
|---|---|---|
| `enable` / `disable` | 自分の翻訳のオン/オフ | 自分に対しては誰でも(他プレイヤー対象はOP) |
| `status` | 現在の状態を表示 | 誰でも |
| `language <code>` | 自分だけ別の言語にする | 自分に対しては誰でも(他プレイヤー対象はOP) |
| `refresh` | APIのクールダウン等を解除し、送信済みのHTTPリクエストを強制中断する(永続的に無効化されたAPIは対象外) | OP、またはシングルプレイのワールドオーナー |
| `config` | サーバーの設定画面を開く(APIキーは通信に乗りません) | OP |

## サーバーで使う

- サーバーにもクライアントにも導入できます。
- **サーバー側per-player翻訳**: サーバー管理者が `serverSideChatTranslationEnabled` を
  有効にすると、サーバーが受信者ごとに翻訳して配信します(送信者本人には翻訳しません。
  オンラインが1人だけのときは本人にも翻訳します)。原文の併記は、サーバー管理者の設定に従います。
- **プレイヤーごとの言語**の決まり方(上から優先):
  1. `/alltranslator language` で選んだ言語
  2. `M`キー設定画面の対象言語(ログイン時と保存時にサーバーへ自動同期。言語コードのみ送信)
  3. サーバーの `forcedTargetLanguage`(個人が未選択のときのサーバー既定値)
  4. Minecraftの表示言語(サーバーに自動で同期されるもの)
  5. `en_us`
- **APIキーの扱い**: クライアントのAPIキーがサーバーへ送られることはありません。
  サーバー側翻訳は、サーバー管理者が自分のサーバーに設定したAPIを使います。
- **サーバー翻訳窓口**(プロバイダ「サーバー経由(プロキシ)」): クライアントがこのAPIを登録すると、
  原文と言語コードだけをサーバーへ送り、サーバー自身のAPIで翻訳した結果を受け取ります。
  サーバー管理者が `serverProxyTranslationEnabled` を有効にしている場合だけ動作します
  (既定はオフ)。オフのときは即座に失敗扱いになり、約30秒間隔で再試行します。
  応答待ちの上限は既定150秒です(`serverProxyTimeoutSeconds`)。
- **サーバー設定画面**: OPが `/alltranslator config` で開き、設定を編集して保存できます
  (APIキー欄はありません。この画面で追加したAPIには資格情報が付きません)。
  ウィンドウが小さすぎる場合は、警告のみを表示します。

## Mod jar一括翻訳

1. タイトル画面が最初に表示されたとき(対象言語ごとに1セッション1回)、対象言語の言語ファイルが無いmodがあれば確認画面が開きます。
2. 翻訳したいmodにチェックを入れて実行すると、modを1つずつ翻訳します。
3. 結果は `config/alltranslator/generated_lang_packs/` に、1つのリソースパック
   「All Translator: generated translations」として書き出され、常時有効になります。
4. 完了後(または画面の「適用」ボタン)でリソースが再読込され、日本語などで表示されます。

- 設定画面の「Modの言語ファイルを翻訳...」から手動でも開けます。
  確認画面の「今後表示しない」で自動表示を止められます。
- 元の `en_us.json` が変わらない限り、再翻訳はしません。生成された `<言語コード>.json` は手で直せます。
- 完全にクライアント側の機能です(サーバーの導入は不要)。

## 設定ファイル

| ファイル | 内容 |
|---|---|
| `config/alltranslator/config.json` | 一般設定・API設定(キー本体は含まない) |
| `config/alltranslator/credentials.json` | APIキー本体(Git管理・共有しないこと) |
| `config/alltranslator/lang/<code>.json` | ユーザー自作の翻訳ファイル(既存翻訳として最優先) |
| `config/alltranslator/player-settings.json` | サーバー側per-player翻訳設定(サーバーローカル) |
| `config/alltranslator/generated_lang_packs/` | Mod jar一括翻訳の生成パック |
| `<world>/alltranslator/translations/` | 翻訳結果の永続キャッシュ(ワールドセーブ内) |

## ローカルLLMを使う場合の注意

- **タイムアウト**: OpenAI互換のHTTPタイムアウトは既定30秒です。7B級の小型モデルは、
  長い文(ツールチップの説明文や長文チャット)に30秒以上かかることがあり、
  その場合はタイムアウトで失敗して一時的にクールダウン状態になります。
  API設定の `extraParams` に `"timeoutSeconds": "120"` のように長めの値を設定してください。
- **同時リクエスト数**: 大型modpackではインベントリを開くたびに大量のリクエストが一度に積まれ、
  非力な環境では数秒〜数十秒かかります。設定画面の同時リクエスト数を小さくすると、
  ローカルLLMへの負荷を抑えられます。詰まったときは `/alltranslator refresh`(`K`キー)で
  送信済みのリクエストを中断できます。
- **翻訳品質**: 7Bクラスの量子化モデルは、固有名詞・専門用語(言語名、曲名、mod用語など)を
  確率的に誤訳することがあります(例: 「Albanian」→「アラビア語」)。モデルの限界であり、
  Mod側のバグではありません。`config/alltranslator/lang/<言語コード>.json` に
  `{"原文": "正しい訳"}` を追加すると、既存翻訳として最優先で使われるので、
  誤訳はこのファイルで上書きしてください。

## 既知の制限

### プロバイダ

- **OpenAI互換(ChatGPT用)・LM Studio**: 実機で動作確認済みです。LM Studio(以前の「ローカル」)は、
  APIキー省略時に `Authorization` ヘッダを送りません。`llama.cpp`(llama-server)は
  同じプロトコルを提供しているとされますが、未検証です。
  以前の「ローカル」の設定は、そのまま使えます(表示名だけが「LM Studio」に変わります)。
- **Ollama**: OpenAI互換のエンドポイント(既定は `http://localhost:11434/v1/chat/completions`)を使う実装ですが、
  **実機では未検証**です(開発環境にOllamaが無いため)。「モデル取得」ボタンは、Ollama側の `/v1/models` への対応を
  確認できていません。うまく動かない場合は、モデル名を直接入力してください。
- **Google Translate Web版(無償・非公式)**: 実機で動作確認済みですが、無償・非公式・無契約の
  エンドポイントのため、IPベース等の理由で予告なくレート制限(HTTP 429)がかかることがあります。
  Mod側のバグではなく、外部エンドポイント側の制約です。Google側の仕様変更で
  動かなくなる可能性もあります。頻繁に制限される場合は、他のプロバイダを優先度上位にしてください。
  そのため**チャット専用**です(プレイヤーチャットと `/msg`・`/tell`・`/w`・`/teammsg`)。
  アイテム名、ツールチップ、`/tellraw`、`/title`、トースト、ボスバー名、Mod jar一括翻訳などには使われません。
  有効なAPIがこれだけの場合、チャット以外は原文のままです。サーバー翻訳窓口(サーバー経由)を通したチャットは、
  サーバー側で「チャット以外」として扱われるため、サーバーの無料Googleは使われません。
- **Anthropic(Claude)・Gemini・DeepL・Google Cloud Translation v2**: 実装済みですが、
  実際のAPIキーでの動作確認は未実施です(DeepL・Google Cloudは、公式ドキュメントに基づく
  モックサーバーでのレスポンス形状の検証のみ)。少量のテキストで動作確認してからお使いください。
- **FTB Quests連携**: 本Mod対象のMinecraftバージョン向けの公式リリースが現時点で存在しないため、
  未実装です(導入されていても検出のみで、クラッシュはしません)。

### 他modの画面

- **libIPN**(Inventory Profiles Next等が使用): 対応済み・実機確認済みです。
- **UI Lib**: 対応済みですが、実際の翻訳動作(テキストの書き換わり)は実機未確認です(検出のみ確認済み)。
- **MaLiLib・Sodium・Cloth Config・YACL・owo-lib**: 表示テキストの読み書きや子要素の列挙を行う
  publicなAPIが無いため、対応を見送っています(非publicフィールドへの `setAccessible` は行わない方針)。
  将来公開APIが追加された場合は再検討します。
- **Iceberg**: 独自のWidget/テキスト体系を持たないため、対応の必要がありません。

### チャットとメッセージ

- **翻訳される範囲**: プレイヤーチャット、`/msg`・`/tell`・`/w`・`/teammsg`、`/tellraw`、
  `/title`、実績の告知です。コマンドのフィードバックや、mod・データパックが生成する
  その他のシステムメッセージは対象外です。
- **`/title`**: コマンドの同期処理の中で送るため、翻訳の完了を待てません。
  同じ文言を2回目に実行したときから翻訳されます(初回は原文、裏で翻訳を開始します)。
- **同一文言の3回以上の連続送信**: リトライキュー方式で大幅に改善されていますが、
  同じ文言が短時間に3回以上送られ、翻訳の完了順序が大きくずれた場合、
  まれに対応がずれる可能性があります。
- **サーバー側翻訳とクライアント側翻訳の二重適用**: クライアント自身の設定で
  `serverSideChatTranslationEnabled` が有効な場合は、二重に翻訳しないようにしています。
  サーバー管理者だけが有効にし、クライアント側は有効でない場合は、二重に翻訳される可能性が
  残ります(恒久対応は予定)。
- サーバー側翻訳では、原文併記(`showOriginalTextInChat`)はサーバー管理者の設定が
  受信者全員に適用されます。個々のクライアントの設定は反映されません。

### その他

- **API選択方式「分散」**: 偽のプロバイダによる単体確認のみで、実際のAPIでの動作は未確認です。
  異常な応答の判定は保守的で、空の応答とプレースホルダーの欠落だけです(長さの異常は判定しません)。
  ローカルの小型モデルは、プレースホルダーを含むテキスト(チャットなど)でトークンを落とすことがあります。
  その場合は失敗として次のAPIに回り、全て失敗すると原文のままになります。
- **JEI連携**: JEIの別名の機能を使い、JEIの検索で、翻訳後の名前でも元の(英語の)名前でも、アイテムを見つけられるようにします。
  - 動作: 英語のゲームで対象言語が日本語の環境で、`ダイヤモンドの剣`で検索してダイヤモンドの剣が見つかることを、Fabricで確認しました。
  - 別名は、原文(英語)の名前と、対象言語の名前(言語ファイルの既存訳、無ければ保存済みの翻訳キャッシュ)です。APIは呼びません。
  - 別名はJEIの起動時(と、リソースの再読込でJEIが再起動したとき)に登録されます。その後に翻訳が終わった名前は、次にJEIが再起動するまで検索に反映されません。
  - JEIは、別名をアイテムのツールチップにも表示します(「Search Aliases:」)。この表示だけを消す設定は、まだありません。消したい場合は、JEIの設定「Search Extra Ingredient Names」をオフにしてください(別名による検索も無効になります)。
  - 日本語のゲームで英語名(例: `diamond sword`)、英語のゲームで日本語名(例: `ダイヤモンドの剣`)、いずれの組み合わせでも別名による検索が効くことを確認済みです(Fabric・NeoForge両方)。
  - **NeoForge**: 実機確認済みです(JEI 30.35.0.223、別名検索・ツールチップ表示とも動作)。
  - **REI**: **非対応です(実装しません)**。別名を追加する公式APIがREIに存在しないことを確認しました(jarを完全展開し、JEIのプラグイン機構への参照が一切無いことを確認済み)。
  - JEI自身のアイテム一覧(インベントリ画面ではなくJEIのグリッド)のツールチップは、既存訳のみが表示され、未翻訳のアイテムでも翻訳APIへのリクエストは発生しません(JEI内部が独自にツールチップを組み立てているため)。
- **ボスバー名**: バニラのエンダードラゴンで確認済みです。mod製ボスは未確認です。
- **LAN参加(ホストではない)クライアント**: 自分ではサーバーを起動しないため、翻訳結果が
  ワールドセーブ内の永続キャッシュに保存されません(メモリキャッシュのみ)。
- **色付きテキスト**: 一部のmod(確認済み: Traveler's Backpack)は、色を `§6` のような
  色コードとしてテキストに直接埋め込みます。All Translatorはこの種の行を色の変わり目で分割し、
  断片ごとに翻訳して、色コードは翻訳APIに渡さず機械的に組み戻します。
  その都合で元の文全体の文脈が失われ、訳文がやや不自然になったり、色の掛かる範囲が
  ずれたりすることがあります(色が消える・無関係な行が着色される、という破損は起きません)。
- **Mod jar一括翻訳**:
  - 翻訳品質は使用するモデルに依存します。生成された言語ファイルは手で直せます。
  - 対象言語のファイルが同じjar内に一部でもあるmodは「翻訳済み」として扱い、不足分は補完しません。
  - 言語ファイルが `assets/<modId>/lang/` にあるmodだけが対象です。名前空間とMod IDが違うmodは検出されません。
  - 別のリソースパックが提供する言語ファイルは考慮しません。
  - 進捗表示はmod単位です(キー数の多いmodは、しばらく「0 / 1」のまま動きません)。
  - ライブラリ(例: Lithostitched内蔵のApolLib)も候補に出ます(チェックを外せます)。
- **NeoForge**: NeoForgeでの動作確認は、専用サーバーの起動、設定画面、ツールチップ、ボスバー、
  Mod jar一括翻訳、`/tellraw`、`/alltranslator config`、サーバー翻訳窓口などに限られます。
  それ以外はFabricでの確認のみの項目があります。

## 開発

Architectury(common/fabric/neoforge)構成。ビルドは以下:

```bash
./gradlew build
```

開発時の実行では、Fabricの専用サーバーは `fabric/run-server`、NeoForgeの専用サーバーは
`neoforge/run-server` を使います(クライアントの設定と混ざらないよう分離しています)。
